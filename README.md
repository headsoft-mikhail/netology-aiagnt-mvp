# MVP консультанта по сетевому оборудованию

Агент интернет-магазина подбирает домашнее сетевое оборудование и отвечает на
вопросы о выборе, совместимости и настройке. Рекомендации строятся по локальной
базе знаний, а цены, характеристики и наличие берутся из SQLite-каталога.

## Возможности

- `search_knowledge_base` ищет инструкции и критерии выбора через RAG.
- `search_products` фильтрует актуальный каталог по категории, характеристикам,
  цене, брендам и наличию.
- CSV-слепок содержит 35 устройств пяти категорий; `product_code` — артикул
  товарной позиции, а не серийный номер отдельного экземпляра.
- Long-term memory хранит только явно сохранённые предпочтения пользователя.
- Short-term memory поддерживает контекст текущего диалога.

## Сценарий и архитектура

Основной путь:

```text
пользователь → AgentRunner → Memory → LLM-планировщик
             → обработчики → ToolRegistry
             → search_knowledge_base → RAG-контекст
             → LLM-фильтры → search_products → товары
             → LLM → итоговый ответ
```

Вызовы Tools, их параметры и результаты сохраняются в trace. Итоговый ответ
может содержать только товары, которые вернул каталог.

Основные компоненты:

- `src/ai_agent/agent.py` — оркестратор и последовательность шагов;
- `src/ai_agent/handlers/` — обработчики памяти, планирования, RAG, каталога и
  финального ответа;
- `src/ai_agent/cli.py` — интерактивный и одноразовый CLI;
- `src/ai_agent/llm/` — конфигурация, клиент и структурированные ответы LLM;
- `src/ai_agent/tools/` — общий протокол, реестр и Tools поиска знаний и товаров;
- `src/ai_agent/rag/` — подготовка источников и retrieval;
- `src/ai_agent/catalog/` — CSV-слепок и SQLite-каталог;
- `src/ai_agent/memory/` — долговременная и сессионная память;
- `tests/` — unit-, сценарные и smoke-тесты.

## Установка

Требуются Homebrew и `just`.

```bash
just setup
just python 3.14.5
just lock && just install
```

Создайте `.env` из `.env.example` и укажите ключ LLM:

```dotenv
LLM_API_KEY=your_api_key
LLM_COMPLETIONS_URL=https://api.groq.com/openai/v1/chat/completions
LLM_MODEL=openai/gpt-oss-20b
```

Настоящий `.env` не добавляется в Git.

## Подготовка и запуск

Каталог и vector store подготавливаются до запуска агента:

```bash
just prepare_agent
```

Интерактивный режим:

```bash
just run_agent
```

Один запрос:

```bash
just run_agent_once "Подбери Wi-Fi 6 роутер до 10 000 рублей"
```

Идентификаторы, логи и структурированный trace можно включить аргументами:

```bash
just -- run_agent_once "Какой роутер подойдёт для тарифа 1 Гбит/с?" --user-id customer-1 --verbose --trace
```

`--debug` добавляет Python traceback для технической диагностики. `--trace` и
`--debug` можно использовать вместе: первый показывает структурированный путь
агента, второй — цепочку исключений. Логи выводятся в `stderr`, отдельно от
ответа агента.

В событии `request_failed` поле `component` показывает место сбоя (`llm`,
`memory`, `search_products` или `search_knowledge_base`), `error_code` —
стабильный код для приложения, а `error_type` и `reason` уточняют техническую
причину, если при сбое было перехвачено исключение.

### Аргументы CLI агента

Аргументы передаются после `just -- run_agent` или после вопроса в
`just -- run_agent_once "вопрос"`.

| Аргумент | Назначение |
| --- | --- |
| `question` | Позиционный вопрос; при его отсутствии запускается интерактивный режим. |
| `--user-id ID`, `--user_id ID` | Владелец долговременной памяти. По умолчанию `local_user`. |
| `--session-id ID`, `--session_id ID` | Идентификатор текущего диалога. По умолчанию генерируется UUID. |
| `--trace` | Печатает в `stderr` JSON-ответ целиком: статус, источники, артикулы, Tool calls, использованную память, ошибки и идентификаторы запроса/сессии. |
| `--verbose` | Печатает в `stderr` основные этапы: память, выбор действий, вызовы Tools, сборку контекста и обращения к LLM. |
| `--debug` | Включает наиболее подробные диагностические логи и stack trace при ошибке; одновременно с `--verbose` не используется. |
| `-h`, `--help` | Показывает встроенную справку CLI. |

### `user_id` и `session_id`

- `user_id` определяет владельца долговременных предпочтений. Используйте один
  и тот же идентификатор, чтобы агент учитывал сохранённый бюджет, бренды и
  другие разрешённые факты в следующих запусках.
- `session_id` связывает сообщения одного текущего диалога. В интерактивном
  режиме история живёт до выхода из процесса; после `end_session` она очищается.
- Не используйте одну `session_id` для разных `user_id`: агент отклоняет такой
  запрос. Между отдельными вызовами `run_agent_once` short-term history не
  сохраняется, даже если передать прежнюю `session_id`.

Проверка памяти и продолжения одной сессии:

```bash
just -- run_agent --user-id customer-1 --session-id consultation-1 --verbose
```

В открывшемся диалоге сначала попросите: `Запомни мой бюджет 10000 рублей`,
затем: `Подбери роутер для тарифа 1 Гбит/с`. После перезапуска с тем же
`user_id` долговременный бюджет останется доступен; история реплик — нет.

## Проверка

```bash
just lint
just test
```

`just test` восстанавливает каталог, пересобирает vector store, выполняет все
тесты и затем очищает runtime-данные.

Обязательные кейсы задания:

- `TC-MVP-001` — основной путь: агент загружает предпочтения, вызывает RAG и
  каталог, собирает контекст и предлагает только реально найденный товар;
- `TC-MVP-002` — ошибочный путь: каталог не находит товар в заданном бюджете,
  агент возвращает `not_found` и не придумывает артикул.

Ещё 26 кейсов проверяют второй основной сценарий, отдельные вызовы каждого
Tool, уточнение, непрофильные вопросы, отсутствие товаров разных категорий,
валидацию и недоступность зависимостей, защиту от выдуманного артикула, операции
памяти, изоляцию `user_id` и контекст/изоляцию `session_id`. Для каждого кейса
записаны `id`, `type`, запрос, ожидаемый и фактический результат, вызванные Tools
и признак прохождения. В начале отчёта поле `required_test_ids` отдельно содержит
ID двух обязательных проверок; сами записи помечены `"required": true`.

Результаты сохраняются в `tests/tests_report.json`. Этот файл одновременно
содержит определения отчётных сценариев: их ID, запросы и ожидаемое поведение.
Сценарные тесты получают запросы оттуда и связываются с кейсами маркером
`report_case`. Во время `just test` pytest фиксирует результат связанного теста,
а после завершения набора автоматически обновляет поле `passed` каждого кейса.
Так тесты и отчёт используют один набор сценариев, а вручную выставлять статус
не требуется.

Контрольный запуск `just test`: **50 passed**.

## Служебные команды

| Команда | Назначение |
| --- | --- |
| `just prepare_agent` | Восстановить каталог и полностью пересобрать vector store перед запуском. |
| `just catalog_restore` | Заново создать SQLite-каталог из версионируемого CSV-слепка. |
| `just catalog_clear` | Удалить сгенерированную БД каталога. |
| `just memory_clear` | Удалить всю локальную долговременную память. |
| `just rag_rebuild` | Очистить и выполнить все стадии подготовки RAG. |
| `just rag_prepare` | Подготовить исходные документы. |
| `just rag_chunk` | Разбить подготовленные документы на фрагменты. |
| `just rag_embedding` | Рассчитать embeddings фрагментов. |
| `just rag_vectorstore` | Создать vector store из готовых embeddings. |
| `just rag_clear` | Удалить все сгенерированные данные RAG. |
| `just clear_runtime` | Очистить память, каталог и сгенерированные данные RAG. |

У служебных Python CLI нет дополнительных флагов, кроме автоматического
`-h`/`--help`; выбор операции сделан отдельными командами `just`.

## Ограничения

- Поддерживается только домашнее сетевое оборудование из локального каталога.
- Цены и остатки не обновляются из внешней системы магазина.
- Для рабочего запуска требуется доступ к настроенной облачной LLM.
- Память не сохраняет адреса, платёжные данные, пароли и токены.

Сбросить память, каталог и vector store можно командой `just clear_runtime`.
После неё для запуска агента снова требуется `just prepare_agent`.
