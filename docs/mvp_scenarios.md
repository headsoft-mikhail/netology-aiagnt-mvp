# Сценарии MVP

## Бизнес-кейс

Интернет-магазин продаёт сетевое оборудование. Покупателю сложно сопоставить
условия использования, технические термины и характеристики десятков моделей.
Агент помогает подобрать товар, объясняет выбор и показывает только доступные
варианты с актуальной ценой.

В магазине используются два источника данных:

- каталог — структурированные и изменяемые сведения о товарах: артикул, категория,
  характеристики, цена и остаток;
- база знаний — руководства по выбору, совместимости и настройке оборудования,
  а также правила доставки, возврата и гарантии.

MVP ограничен домашним сетевым оборудованием: роутерами, mesh-системами,
коммутаторами, Wi-Fi-адаптерами и точками доступа.

## Ответственность компонентов

- `search_knowledge_base` получает из RAG объяснения и критерии выбора.
- `search_products` фильтрует локальный каталог по точным характеристикам, цене
  и наличию.
- Long-term memory хранит только явно сохранённые предпочтения покупателя.
- Short-term memory хранит контекст текущего диалога и уточняющих реплик.
- LLM выбирает действия, преобразует условия покупателя в аргументы Tools и
  объясняет итог, но не выдумывает товары, цены и свойства.

Товарные карточки не дублируются в RAG. База знаний отвечает на вопрос «какие
критерии важны и почему», а каталог — «какие конкретные товары подходят сейчас».

## Источники базы знаний

Для MVP нужен небольшой согласованный набор документов:

- выбор роутера по площади, числу устройств и скорости тарифа;
- различия Wi-Fi 5, Wi-Fi 6 и Wi-Fi 6E;
- покрытие, помехи, mesh-системы и репитеры;
- скорости WAN/LAN-портов и категории Ethernet-кабелей;
- совместимость с распространёнными типами подключения провайдера;
- базовая настройка и безопасность домашней сети;
- типовые неисправности подключения;
- доставка, возврат и гарантия магазина.

## Вход и выход агента

Обязательный вход:

- `message` — непустой текст запроса;
- `user_id` — идентификатор владельца долговременной памяти;
- `session_id` — идентификатор текущего диалога.

Результат содержит:

- `status`: `success`, `needs_clarification`, `not_found` или `error`;
- `answer` — итоговый ответ либо понятное следующее действие;
- `tool_calls` — имена, безопасные аргументы и статусы вызванных Tools;
- `products` — товары, фактически возвращённые каталогом;
- `sources` — документы и фрагменты, использованные для объяснения;
- `memory_used` — идентификаторы использованных записей памяти;
- `request_id` и `session_id` для сопоставления результата с логами.

## Контракт `search_products`

Tool принимает типизированные фильтры каталога:

- название либо артикул для поиска конкретного товара;
- категорию товара;
- максимальную цену;
- минимальный стандарт Wi-Fi;
- минимальную скорость WAN/LAN-портов;
- необходимость поддержки mesh;
- включённые или исключённые бренды;
- требование наличия на складе;
- сортировку и ограничение числа результатов.

Общие поля и отдельный набор характеристик роутера будут описаны Pydantic-моделями.
Tool выполняет фильтрацию в локальной БД и возвращает применённые фильтры, артикул,
название, цену, остаток и необходимые для сравнения характеристики. Порядок и
лимит результатов задаются явно. Tool не интерпретирует бытовой запрос, не
придумывает преимущества товара и не подменяет отсутствующие позиции похожими
без решения агента.

## Основной сценарий: подбор роутера

**Предусловие.** Пользователь явно попросил запомнить бюджет до 15 000 рублей и
исключить один нежелательный бренд.

**Запрос:** «Подбери роутер для квартиры 80 м², тарифа 1 Гбит/с и десяти
устройств».

Последовательность:

1. Агент валидирует запрос и загружает релевантные предпочтения из памяти.
2. `search_knowledge_base` находит руководство по покрытию, стандартам Wi-Fi и
   скорости портов.
3. LLM-планировщик преобразует запрос, память и найденные критерии в
   валидированные фильтры каталога: гигабитные порты, подходящий стандарт Wi-Fi,
   поддержка требуемого покрытия, бюджет и исключённый бренд.
4. `search_products` выполняет запрос к локальной БД и возвращает доступные
   модели с актуальными ценами и характеристиками.
5. LLM формирует краткий список вариантов, объясняет различия на основании
   источников и не упоминает товары, которых не было в результате Tool.

Проверяемый результат: вызваны оба Tools, в фильтрах присутствуют условия запроса
и памяти, каждый предложенный товар есть в результате каталога, цена и остаток
совпадают с БД, а объяснение опирается на найденные документы. Обычный вопрос не
изменяет память.

## Ошибочный сценарий: подходящих товаров нет

**Запрос:** пользователь задаёт сочетание цены и характеристик, которому не
соответствует ни один товар в наличии.

Агент получает критерии через RAG, вызывает каталог и получает пустой результат.
Он возвращает `status=not_found`, не выдумывает товар и сообщает, какое
ограничение можно пересмотреть. Повторный поиск с ослабленным условием выполняется
только после согласия пользователя.

## Альтернативные сценарии

- «Есть ли модель X и сколько она стоит?» → только `search_products`.
- «Чем mesh отличается от репитера?» → только `search_knowledge_base`.
- «Покажи более дешёвые варианты» → short-term memory восстанавливает предыдущие
  критерии, после чего повторно вызывается `search_products`.
- «Запомни: мой бюджет — 15 000 рублей» → обновляется long-term memory, предметные
  Tools не вызываются.
- Неполный запрос «Посоветуй хороший роутер» → агент запрашивает площадь,
  количество устройств, скорость тарифа и бюджет до поиска товаров.
- Неподдерживаемый запрос → Tools не вызываются, агент сообщает границы MVP.
- Отказ RAG, каталога или LLM → `error` с безопасным сообщением без ложного
  результата успешного выполнения.

## Политика памяти

По явной просьбе можно сохранять бюджет, предпочтительные и исключённые бренды,
площадь помещения, число устройств, скорость тарифа и уже имеющееся сетевое
оборудование. Новое значение того же ключа заменяет старое. Платёжные данные,
адрес, пароли Wi-Fi, токены и другие секреты не сохраняются.

В запрос передаются только релевантные записи с лимитом. Данные памяти считаются
предпочтениями пользователя, а не источником сведений о цене, наличии или
характеристиках товара.
